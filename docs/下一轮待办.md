现状：`settings.reader` 只有一套 `fontSize / lineHeight / pageWidth / padding`，两个模式共用 ✗。

改法（**逐块改，每步跑 typecheck**）：

1. `src/shared/types.ts` → `ReaderSettings` 加 4 个可选字段：
   `pagedFontSize? / pagedLineHeight? / pagedPageWidth? / pagedPadding?`（不改现有字段，保证兼容）
2. `src/pages/ReaderPage.tsx` 的 `readerStyle`（约 457–461 行）→ 四个 CSS 变量按 `mode` 取值：
   `mode === 'paged' ? (readerSettings?.pagedX ?? readerSettings?.X ?? 默认值) : (readerSettings?.X ?? 默认值)`
   并把 `mode` 加进 `useMemo` 依赖数组（现在没有）。
3. 排版面板（约 833–857 行的「字号」「行距」两个 `.panel-row`）→
   滑块的 `value` 与 `onChange` 都按当前模式读写；面板标题改成「排版设置 · 滚动 / 翻页」。

## 二、版心宽度真正生效（用户反馈"没效果"）

两个原因叠加：

- **滚动模式**：`--reader-width` 默认 720px，在 390px 宽的屏上永远不触发 `max-width` ✗；
  而且滑块 `min={480}` → 永远够不到有效区间 ✗。
  → 下限改 **240**；`.reader-page` 已加 `margin: 0 auto`（比屏窄时居中）。
- **翻页模式**：栏宽是 **JS 分页算出来的**（`screenWidth / columns / columnWidth`，约 60–75 行）✗，
  `--reader-width` 在那里**根本没被读** ✗。
  → 把 `pageWidth` 接进分页计算：`columnWidth = min(可用宽, pageWidth)`。

## 三、页边距在翻页模式生效（用户反馈"只有滚动有效"）

翻页模式分页按 `bodySize`（元素内容宽）算栏宽 ✗ → padding 变量没参与计算 ✗。
→ 分页可用宽改成 `元素宽 − 2 × padding`。

## 四、已知坑（本轮踩过，务必遵守）

1. **不要用一整段 PowerShell 正则批量改 JSX** —— 转义地狱 + 无法逐块验证 ✗
   （本轮一次因转义整段解析失败、一次把 JSX 改坏，都回滚了）。
   → 改成：读一块 → 改一块 → `npm run typecheck` → 再改下一块。
2. **edit 工具要求"先读后写"** —— 同一文件被 PowerShell 改过之后，必须重新 `read` 才能 `edit`，
   否则报 `file changed since it was read`（本轮因此发过一版"代码与提交信息不符"的包 ✗）。
3. **发布守卫**：构建前用 grep 校验每处改动是否真的落地，缺一即 `exit 1` 中止发布
   （已实现，两次成功拦下不符的包 ✓）。
4. **`!important` 要用在明处**：手机端曾写死 `--reader-padding: 18px` ✗，导致设置页「页边距」永远无效；
   同理 `.reader-progress`、`.slider` 都有旧规则需要覆盖 —— 写 `!important` 时必须紧跟注释说明在压哪条规则。
5. 探针（`scripts/ui-probe.mjs`）要跑**四个页面**看 console 报错：阅读器曾经因为 hooks 顺序崩溃过 ✗。
