# 手机端数据层方案（下一步开发内容）

> 现状：手机端**只有界面 + 内存假数据**（`window.api` = `src/lib/mock-api.ts`）。
> 界面第一版已完成并存档（tag `ui-v1-界面版`）。本文件是数据层的实施方案。

## 目标（按优先级）

1. 手机上能看到**自己的书**、能翻页读（真目录 + 真正文 + 真封面）；
2. 进度与阅读时长**本地持久化**，重启不丢；
3. 接**网盘同步**，与桌面端共用同一个云端格式（`/DshReader/{manifest,progress,sessions,devices,books}`）。

## 分层

```
src/data/
  db.ts        IndexedDB 封装：books(元数据) / files(EPUB Blob) / chapters(解析结果) / progress / sessions
  store.ts     业务读写：书库列表、单本详情、进度、时长、统计
  epub.ts      EPUB 解析（从桌面端 src/main/epub.ts 移植：fs → Uint8Array）
  import.ts    导入：选文件 → 落库 → 解析 → 入册
src/api/local.ts    window.api 的本地实现（library / reader / stats / settings 四组）
src/api/webdav.ts   网盘同步（复用探路页验证过的原生 HTTP 通道）
```

替换点只有一处：`main.tsx` 里 `window.api = createLocalApi()` 取代现在的 `createMockApi()`。
界面代码一行都不用改（`DshApi` 类型两边同一份）。

## 实施顺序（每步都能单独验证）

1. **先用真实数据打通渲染链路（不碰解析）**
   写一个桌面脚本，用**桌面端已跑通的解析器**把一本书导出成
   `public/data/library.json` + 每章 JSON + 封面 → 手机端 `local.ts` 直接读它。
   价值：真目录 / 真正文 / 真封面 一次性跑通，验证 `DshApi` 形状与阅读器渲染。
2. **EPUB 解析移植**：把 `src/main/epub.ts` 移植成 `src/data/epub.ts`（fs → Uint8Array），
   用第 1 步同一本书做**回归对比**（章节数、字数、封面一致才算移植成功）。
3. **导入与持久化**：Capacitor Filesystem + 文件选择器 → `db.ts` 入库；
   进度与时长写入 IndexedDB（离线可读、重启不丢）。
4. **网盘同步**：`webdav.ts` 接上第 3 步的数据；云端格式不变。
5. **收尾**：删掉 `mock-api.ts` 与临时的 `public/sample-cover.jpg`。

## 约束与经验

- 桌面端 `src/main/{epub,library,naming}.ts` 是纯 JS 逻辑（`fflate` + `fast-xml-parser`），
  可以整段移植；**不要**引入 Electron 专有 API（`mediaUrl` 已改成原样返回 ✓）。
- 手机上**不要**依赖 `%APPDATA%`/文件路径那套：数据一律进 IndexedDB（或 Capacitor Filesystem）。
- 布局类问题先**量**再改：`scripts/ui-probe.mjs` 会打印元素的实际宽高与 `min-width/min-height`。
  今晚三个坑都出在这里 —— `min-width: auto` 顶宽网格、`min-height` 顶掉 `height`、
  内联 `width: 640` 把弹窗撑到视口外。
- 验证一律走**手机视口**（`node scripts/shot-mobile.mjs` 或 ui-probe），
  不要用 `--window-size=390`（Windows 上最小窗口宽 ~585，媒体查询不生效）。
